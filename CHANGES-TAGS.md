# Tag Export Changes

This document records the tag-export and right-sidebar changes implemented in this branch.

## Scope

The work changed tag export from a per-page inline chip display into a vault-level tag tree rendered in the right sidebar, while preserving the original right-pane content as a separate switchable view.

## Files Changed

### Exported metadata

- `src/shared/website-data.ts`
  - Added `TagTreeItemData`.
  - Added `WebsiteData.tagTree` for vault-level exported tag hierarchy data.

- `src/plugin/website/index.ts`
  - Added `buildTagTree()`.
  - Builds a nested tag tree from exported page metadata during `finalize()`.
  - Counts tags per node and per parent path.
  - Sorts nodes by descending count, then alphabetically.
  - Respects `showInlineTags` and `showFrontmatterTags` options when building the tree.

- `src/plugin/website/webpage.ts`
  - Fixed tag export bug by writing `output.inlineTags = this.inlineTags`.
  - This was necessary because the sidebar tree reads exported metadata, not live Obsidian cache state.

### Tag feature placement and runtime behavior

- `src/shared/features/tags.ts`
  - Moved the `tags` feature placement from `.header .data-bar` to `#right-sidebar-content`.
  - Left `displayTitle` empty because the custom tag pane now renders its own header.

- `src/frontend/main/website.ts`
  - Changed tag feature runtime from per-document tag lists to a vault-level `metadata.tagTree` view.
  - The tag pane now appears whenever the tags feature is enabled, not only for markdown pages with current-note tag content.

- `src/frontend/main/search.ts`
  - Fixed filtered search parsing so `tag:...`, `tags:...`, and `#...` queries search the tag index correctly.
  - Uses normalized filter values instead of passing the entire prefixed query string into field-limited searches.

### Right sidebar tag UI

- `src/frontend/main/tags.ts`
  - Replaced the old simple anchor list with a tree-based tag pane.
  - Added a `RightSidebarViewManager` that:
    - Preserves original right-sidebar content in one panel.
    - Moves the tag feature into a separate tags panel.
    - Adds a persistent view switcher in the right sidebar top bar.
    - Stores the selected panel in `localStorage` using `right-sidebar-active-view`.
  - Added icon-based buttons for:
    - `Table of contents & Interactive graph`
    - `Tags`
  - Added a custom `Tags` pane header inside the scrollable tree area.
  - Restored expand/collapse-all functionality by keeping the collapse button inside the tree root expected by the existing `Tree` runtime.
  - Hides the autogenerated feature header to avoid duplicate `Tags` labels.
  - Keeps the tag header row sticky while scrolling.

### Styling

- `src/assets/plugin-styles.txt.css`
  - Added layout and styling for:
    - tag tree container
    - per-tag counts
    - nested tag indentation
    - right sidebar view switcher
    - icon tab active/hover states
    - original/tags panel split
    - sticky tag pane header
    - independent scroll behavior for the tag tree
  - Ensures the original right-sidebar panel remains scrollable.
  - Ensures the tags panel is independently scrollable without hiding the rest of the right-sidebar content model.

## Behavior Changes

### Before

- Tags were rendered as inline links in the page header data bar.
- The exported site had no vault-level tag browser.
- Right sidebar content only exposed the existing outline / backlinks / graph style content.

### After

- Exported metadata now contains a vault-level nested tag tree.
- The exported site shows a dedicated `Tags` view in the right sidebar.
- The right sidebar has two switchable modes:
  - `Table of contents & Interactive graph`
  - `Tags`
- Tag nodes:
  - support nesting by `/`
  - show aggregate counts
  - are searchable through existing `tag:` search flow
  - support collapse/expand behavior using the existing tree component

## Bugs Fixed During Implementation

- Fixed empty exported `tagTree` caused by missing `output.inlineTags`.
- Fixed duplicate `Tags` heading caused by the generated feature header and the custom pane header both rendering.
- Fixed lost expand/collapse-all behavior caused by moving the collapse control outside the tree root.
- Fixed tag query routing so clicking tag entries triggers correct tag-only search behavior.

## Environment and Build Changes

- `package.json`
  - Added engines constraint: `node >=18 <25`.

- `.nvmrc`
  - Added `24`.

- `AGENTS.md`
  - Added repository environment notes describing the Node 24 requirement and the working install/dev commands used in this environment.

## Runtime Compatibility Note

The repository installed and ran correctly under Node 24, but not under the machine-default Node 25. No Electron version change was required; the issue was Node/runtime compatibility with the pinned toolchain.
